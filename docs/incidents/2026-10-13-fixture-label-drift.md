# Incident: golden fixture label drift

- **Date:** 2026-10-13
- **Detected by:** `tests/test_gold_fixture.py` (the golden-set check)
- **Severity:** high - gold labels disagreed with the service on 95 of
  300 rows; shipping would have meant grading the service against
  labels it could never reproduce.
- **Status:** fixed, regression-guarded (commits `8cd0ecd` red ->
  `06ec11a` green).

## Diagnosis

1. **Per-row diff of twin vs gold labels.** All 9 acuity
   disagreements contained the symptom `minor_cut`
   (e.g. `triage-0009`, `triage-0040`).
2. **Root cause A - duplicated rule tables.** The fixture generator
   kept its own severity table with `minor_cut -> high`; the runtime
   `SYMPTOM_SEVERITY` table did not contain `minor_cut` at all. The
   runtime was even internally inconsistent: the router treated
   `minor_cut` as an emergency token while the twin scored it as
   unrecognised (moderate ceiling).
3. **Root cause B - acuity-blind routing.** The generator labelled
   `expected_department` with an acuity-aware function
   (`high -> urgent_care`, routine before fever), while the router
   chose endpoints from symptom tokens only. That single mismatch
   class accounted for the bulk of the 86 endpoint disagreements
   (endpoint_accuracy 0.7133), e.g. `triage-0003`
   (`routine_checkup` + patient-reported high: gold `urgent_care`,
   runtime `general_practice`).
4. **Root cause C - test harness dropped a field.** After the shared
   policy fix the eval reached 1.0000 but the golden test still
   failed on `triage-0001`. Cause: the test built `TriageRequest`
   without `vitals`, so a row whose gold label came from
   heart_rate 127 was assessed as if the patient had no vitals
   (`moderate` instead of `high`):

   ```
   triage-0001 gold=high  test-view=moderate  full-view=high  MISMATCH
   ```

   Capture: `docs/evidence/gold_fixture_vitals_drop_failure.txt`.

## Fix (commit `06ec11a`)

- Extracted `src/afyaplus/triage/policy.py` as the **single source of
  truth** for symptom severities, vitals thresholds, age escalation
  and routing order. The domain twin, the router and the fixture
  generator all import it - one copy of the rules.
- Made routing acuity-aware, in the documented order: red-flag
  symptom -> high acuity -> routine -> urgent -> default.
- Regenerated the fixture with the same seed (row bodies unchanged;
  only the labels that had drifted were corrected).
- Fixed the golden test's field mapping to forward
   `vitals=fixture.get("vitals", {})`. **The assertion itself was not
  weakened** - it still requires exact recommendation agreement.

## Why it cannot silently recur

- One policy module feeds runtime *and* labels; editing rules without
  regenerating the fixture makes the golden test fail.
- The pin manifest fingerprints the rule table
  (`model_pin.digest`); a rule change without
  `python -m src.afyaplus.pins.manifest` fails `test_pin_fields`.
- `scripts/eval_score.py` exits non-zero below the 0.90 threshold, so
  CI would go red on drift.
- The golden test remains in the default test tier, so every
  `pytest -q` re-checks the contract.

**Lesson:** a golden set is only as honest as the independence of its
labels. Here the labels were generated by a *second copy* of the
rules rather than the rules themselves, which is precisely what made
the drift invisible until the test caught it.
